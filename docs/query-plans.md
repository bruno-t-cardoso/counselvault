# Query plans

Generated by `python manage.py benchmark_queries`. Do not edit by hand.

Each query below is the ORM query the API actually runs, executed for one firm under
row-level security. Times are the median `EXPLAIN ANALYZE` execution time of 7 runs with
a warm cache. "Without" drops the listed indexes inside a savepoint and measures again.

**Read these as relative, not absolute.** The data is synthetic and uniformly
distributed, and this ran on PostgreSQL 16.15 (Debian 16.15-1.pgdg13+2) in Docker on a laptop.

## Full-text search

`GET /api/search/?q=term42`: ranked, latest versions only, minus walled-off matters.

The GIN index makes no difference here, and the plan shows why: it is not used. Under row-level security PostgreSQL only uses an operator as an index condition if it is marked leakproof, and the text-match operator `@@` is not. The planner reads the firm's rows through the `firm_id` index and filters them. Marking `ts_match_vq` leakproof (superuser only) makes the planner use the GIN index.

Indexes used: `vault_document_firm_id_4e0e9f0b`, `vault_documentversion_firm_id_63fdd29c`, `version_number_once`.
